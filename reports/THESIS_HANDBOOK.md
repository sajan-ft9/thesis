## Part 0 — The thesis in one page

**Problem.** Pneumonia kills, especially children in low-resource settings; expert chest
X-ray (CXR) reading is scarce. Deep models can help, but big models are heavy and opaque,
and most published CXR results are reported *dishonestly* (no leakage control, accuracy-only,
no real efficiency/memory numbers).

**What I built.** A lightweight **EfficientNet-B0** pneumonia classifier with **Grad-CAM++**
explanations and **INT8 quantization**, evaluated *the way it would be deployed*: with
data-integrity checks, confidence intervals, correct memory benchmarking, and **zero-shot
external validation** on a second dataset (RSNA).

**The real contribution = the methodology, not the classifier.** Five contributions:
(1) data-integrity, (2) reproducibility, (3) explainability, (4) a real dynamic-vs-static
quantization study, (5) correct efficiency/memory measurement.

**Headline numbers.** Internal test AUC **0.9678**; static INT8 → **5.13 MB (−71%), ~8×
faster CPU, ~6× less RAM**, 2.3-pt AUC cost; streaming loader uses **9.4× less RAM**;
external RSNA AUC **0.8892** (expected domain-shift drop). Every number is regenerated by
code and machine-checked (`make verify-numbers`, 21/21).

**One-sentence defense.** *"I didn't try to beat an accuracy record — I built an honest,
reproducible, deployment- and memory-aware evaluation of an explainable, quantized pneumonia
detector, and I tested it on a second dataset to show it generalises."*

## Part 1 — Glossary

For each term: **plain meaning** → *in this thesis*.

### 1A Medical / clinical
- **Pneumonia** — lung infection causing the air sacs to fill with fluid/pus, visible on CXR as opacities. *Target positive class.*
- **Chest X-ray (CXR)** — 2-D radiograph of the chest. *Model input.*
- **Opacity / consolidation** — whiter (denser) regions on a CXR where air is replaced by fluid; the radiological sign of pneumonia. *What the model and Grad-CAM++ should focus on.*
- **AP / PA view** — Anterior-Posterior / Posterior-Anterior projection (X-ray direction). *Kermany is pediatric AP; RSNA is adult.*
- **Screening vs. diagnosis** — screening = cheap first-pass flag to catch likely cases; diagnosis = definitive call by a clinician. *This model is positioned as a screening / decision-support tool, NOT a diagnostic device.*
- **Sensitivity (recall, true-positive rate)** — of all real pneumonia cases, the fraction the model catches. *Prioritised: missing pneumonia (false negative) is clinically worse than a false alarm.*
- **Specificity (true-negative rate)** — of all normal cases, the fraction correctly called normal. *Lower specificity = more false alarms.*
- **False negative (FN) / false positive (FP)** — missed pneumonia / false alarm. *We report both; FN is the dangerous one for screening.*
- **Pediatric** — children (Kermany: ages 1–5). *Source of the train data; adults (RSNA) are the domain-shift test.*

### 1B Dataset & data integrity
- **Kermany dataset** — public pediatric CXR set (Normal vs Pneumonia), ~5,856 images. *Primary dataset (train + held-out test).*
- **RSNA Pneumonia Detection Challenge** — public, expert-adjudicated CXR set (Normal / Lung Opacity / No Lung Opacity-Not Normal), adult, NIH-sourced. *External validation dataset.*
- **NIH ChestX-ray14** — large multi-label CXR set with NLP-mined (noisy) labels. *Considered but deferred (45 GB, noisy pneumonia label); see feasibility report.*
- **Class imbalance** — unequal class sizes (Kermany is ~73% pneumonia). *Handled via stratified splitting and label smoothing; we report sensitivity/specificity, not just accuracy.*
- **Train / validation / test split** — train = learn weights; validation = tune/decide when to stop (model selection); test = final, untouched evaluation. *Stratified 80/20 from the train folder; official test held out.*
- **Stratified split** — split that preserves class proportions in each part. *`stratified_split()` in `dataset.py`.*
- **Held-out test set** — data never seen during training/selection. *Kermany official test (624 images) — the primary metric.*
- **Data leakage** — when information from test/val sneaks into training, inflating results. *Two kinds: byte-identical duplicates and patient-level overlap.*
- **Duplicate detection (MD5 / content hash)** — hashing image bytes to find identical files. *`find_duplicates()`; found 16 duplicate groups in train; removed 26 files.*
- **Leakage check** — verifying splits share no image by path or content. *`verify_no_leakage()`; raw split had 9 train↔val content leaks → cleaned.*
- **Deduplication** — removing duplicate images before splitting. *`deduplicate_samples()`; keeps the test set canonical.*
- **Domain shift** — train and test data come from different distributions (here pediatric→adult, different scanners). *The reason RSNA AUC < Kermany AUC; expected.*
- **Zero-shot evaluation** — testing a trained model on new data with no further training/tuning. *How RSNA is evaluated.*
- **Internal vs external validation** — same-source held-out test (internal) vs a different dataset (external). *Kermany = internal; RSNA = external.*

### 1C Deep learning & model
- **CNN (convolutional neural network)** — neural network using convolution filters to learn image features. *All three models are CNNs.*
- **EfficientNet-B0** — a small, efficient CNN using *compound scaling* and depthwise-separable convolutions. *The proposed backbone (~5.3 M base params; 4.34 M in our model after head swap).*
- **Compound scaling** — EfficientNet's idea of scaling depth, width, and input resolution together. *Why EfficientNet is efficient.*
- **Depthwise-separable convolution** — a convolution factorised into per-channel + 1×1 steps; far fewer operations. *Used by EfficientNet & MobileNet.*
- **ResNet-18 / MobileNetV3-Small** — baseline CNNs (residual connections / mobile-optimised). *Trained with the identical pipeline for a fair comparison.*
- **Backbone / feature extractor** — the part of the network that turns an image into a feature vector. *The pretrained CNN body.*
- **Classifier head** — the final layers mapping features → prediction. *Our shared head: `BatchNorm1d(1280)→Dropout(0.3)→Linear(1280,256)→ReLU→Dropout(0.2)→Linear(256,1)`.*
- **Transfer learning** — reuse weights learned on a big dataset for a new task. *We start from ImageNet weights.*
- **ImageNet pretraining** — weights pre-learned on the 1.2 M-image ImageNet set. *Initial backbone weights.*
- **Logit** — the raw, pre-activation output number. *Single logit → sigmoid → pneumonia probability.*
- **Sigmoid** — squashes a logit to a probability in [0,1]. *Used at inference.*
- **Parameters** — the learnable weights. *EfficientNet-B0 4.34 M, MobileNetV3-Small 1.08 M, ResNet-18 11.31 M (our configs).*
- **BatchNorm / Dropout / ReLU** — normalisation layer / random unit drop (regularisation) / non-linear activation. *All in the head.*

### 1D Training
- **Epoch / batch / mini-batch** — one full pass over the data / a group of samples processed together / same. *Batch size 32; up to 20 epochs.*
- **Loss function** — the number being minimised. *Binary cross-entropy (BCE).*
- **Binary cross-entropy (BCE)** — standard loss for binary classification. *With label smoothing.*
- **Label smoothing** — softening hard 0/1 targets (toward 0.5) to reduce over-confidence. *α = 0.05; `SmoothBCELoss`.*
- **Optimiser / AdamW** — algorithm that updates weights; AdamW = Adam with decoupled weight decay. *lr 3e-4 (head) → 3e-5 (fine-tune), weight decay 1e-4.*
- **Learning rate (LR) & schedule** — step size; how it changes over time. *3-epoch linear **warmup** then **cosine annealing**.*
- **Warmup / cosine annealing** — ramp LR up gently, then decay it on a cosine curve. *Stabilises early training, anneals later.*
- **Weight decay** — L2 regularisation discouraging large weights. *1e-4.*
- **Gradient clipping** — capping gradient magnitude to prevent exploding updates. *Max-norm 1.0.*
- **Mixed precision (AMP) / GradScaler** — train partly in 16-bit for speed; scaler prevents underflow. *Enabled on CUDA only; our run used Apple MPS in fp32.*
- **Freeze / unfreeze (staged transfer learning)** — keep early layers fixed first, then train all. *Head-only warmup, then unfreeze full backbone at a set epoch with a lower LR.*
- **Fine-tuning** — continuing training of (unfrozen) pretrained layers on the new task. *Phase 2 of training.*
- **Early stopping** — stop when validation stops improving. *Patience 7 epochs on validation AUC.*
- **Checkpoint** — saved model weights (best epoch). *`models/<name>_best.pth`.*
- **Seed / determinism** — fixing randomness so runs are reproducible. *`seed_everything(42)` + seeded DataLoader.*
- **DataLoader / num_workers** — batches data from disk; workers = parallel loaders. *Lazy, path-based (memory-safe).*

### 1E Evaluation & statistics
- **Confusion matrix (TP/TN/FP/FN)** — counts of correct/incorrect per class. *Reported per dataset.*
- **Accuracy** — fraction correct overall. *Can mislead under imbalance — hence the others.*
- **Precision** — of predicted-pneumonia, fraction truly pneumonia. *Tied to false-positive rate.*
- **Recall / sensitivity** — see 1A. **Specificity** — see 1A.
- **F1-score** — harmonic mean of precision and recall (balances both). *0.9366 internal.*
- **ROC curve** — sensitivity vs (1−specificity) across thresholds. *Figure per dataset.*
- **ROC-AUC** — area under the ROC curve; threshold-independent separability (0.5 = chance, 1 = perfect). *Primary metric: 0.9678 internal, 0.8892 external.*
- **Precision-Recall (PR) curve** — precision vs recall; informative under imbalance. *Generated in evaluation.*
- **Decision threshold** — probability cutoff for "pneumonia" (default 0.5). *Kept fixed; never tuned on the test set.*
- **Youden's J** — threshold maximising (sensitivity + specificity − 1); a balanced operating point. *Reported for context; **not** applied to change results.*
- **Operating point** — the chosen sensitivity/specificity trade-off (a deployment choice). *Default vs Youden discussed.*
- **Bootstrap** — resampling the test set with replacement many times to estimate variability. *1,000 resamples.*
- **Confidence interval (95% CI)** — range that plausibly contains the true value. *e.g. AUC 0.9678 [0.9504, 0.9816].*

### 1F Quantization & efficiency
- **FP32 / INT8** — 32-bit float / 8-bit integer number formats. *We compress FP32 → INT8.*
- **Quantization** — representing weights/activations in lower precision to shrink & speed up the model. *Core to the "quantized" title.*
- **Dynamic quantization** — quantizes *linear* layer weights only; activations quantized at runtime. *Easy but small gain on conv-heavy nets (~6%).*
- **Static post-training quantization (PTQ)** — quantizes weights *and* activations, using a calibration pass; covers convolutions. *The deployment-relevant one: −71% size.*
- **Calibration** — running representative data through the model to set activation ranges. *On the clean validation set (never augmented train, never test).*
- **Per-tensor vs per-channel** — one scale for a whole weight tensor vs one per output channel. *Key finding: per-tensor collapses EfficientNet (AUC ~0.40); per-channel recovers it (0.9444).*
- **Observer (MinMax / Histogram)** — module that records value ranges during calibration to pick quantization scales. *Histogram observer for activations.*
- **qconfig / backend (qnnpack, fbgemm)** — the quantization recipe / the CPU kernel library that runs INT8. *Backend `qnnpack` (ARM/Apple).*
- **FX graph mode quantization** — PyTorch API that traces the model graph to insert quant ops. *Used for static PTQ.*
- **ONNX** — open model format for cross-platform deployment. *FP32 model exported + verified.*
- **Latency** — time per inference (ms/image). *~120 ms FP32 → ~15 ms INT8 (CPU).*
- **Throughput** — images processed per second (batched). *~19 img/s FP32.*
- **Warmup runs** — discarded first runs so timing excludes one-off setup costs. *Used in benchmarking.*
- **RSS (Resident Set Size)** — actual physical RAM a process uses. *Measured with psutil sampling — the honest memory metric.*
- **`tracemalloc` (and why NOT)** — Python-only allocation tracker; ignores tensor/library memory → absurd "0.1 MB" figures. *Explicitly avoided; the original draft's mistake.*
- **Model size on disk** — serialized weight file size (MB). *17.66 MB FP32 → 5.13 MB INT8.*
- **Edge device** — constrained hardware (Raspberry Pi, Jetson). *Deployment target; we use CPU as a *proxy* (no physical device run).*

### 1G Explainability
- **Explainability / interpretability** — making a model's decision inspectable by humans. *Via Grad-CAM++.*
- **Saliency map / heatmap** — image overlay showing which pixels drove the prediction. *Grad-CAM++ output.*
- **CAM → Grad-CAM → Grad-CAM++** — family of methods producing class-discriminative heatmaps from CNN activations and gradients; ++ improves localisation. *We use Grad-CAM++.*
- **Target layer** — the conv layer whose activations/gradients are visualised (usually the last). *`get_cam_target_layers()`.*
- **Faithfulness** — whether the heatmap truly reflects the model's reasoning. *We make NO clinical-alignment claim; explanations are qualitative.*

### 1H Software & reproducibility
- **Reproducibility** — anyone can regenerate the exact results from the code + data. *Core contribution; `make reproduce`.*
- **Config-as-code / YAML / dataclass** — experiment settings in version-controlled files, loaded into typed objects. *`configs/`, `config.py`.*
- **CLI (command-line interface)** — running a stage as `python -m src.<stage>`. *Every stage.*
- **Unit vs integration test** — test one function vs test stages working together. *40 tests in `tests/`.*
- **Fixture** — reusable test setup (here a tiny synthetic dataset). *`tests/conftest.py`.*
- **Manifest / `metadata.json`** — per-run record (timestamp, git SHA, seed, versions, config). *Written by training.*
- **MPS / CUDA / CPU** — Apple GPU backend / NVIDIA GPU / processor. *Trained on MPS; CUDA supported; inference benchmarks on CPU.*

## Part 4 — Coding flow walkthroughs

**`make train` → `python -m src.train --config configs/efficientnet_b0.yaml`**
1. `config_from_cli` → `load_config` merges `base.yaml` + model YAML + CLI overrides → `Config`.
2. `train(cfg)`: `seed_everything(42)` → `get_device()` (MPS).
3. `build_dataloaders`: `scan_split(train)` + `scan_split(test)` → `deduplicate_samples(train)` (removes 26) → `stratified_split` (train 4152 / val 1038) → wrap in `ChestXRayDataset` with train/eval transforms → DataLoaders (seeded).
4. `build_model("efficientnet_b0", pretrained=True, freeze_stages=5)` → torchvision backbone, classifier replaced by the shared head, early stages frozen.
5. Loss `SmoothBCELoss(0.05)`, optimiser `AdamW`, `GradScaler` (AMP off on MPS), `build_scheduler` (warmup+cosine).
6. Epoch loop: at `unfreeze_epoch` → `unfreeze_all()` + new optimiser at 0.1× LR; `run_epoch(train)` (forward → BCE → backward → clip → step), then `run_epoch(val, no_grad)`; track best **val AUC**; save `*_best.pth`; **early-stop** after patience 7.
7. Load best weights; write `*_history.csv/json`, `*_metadata.json` (+ TensorBoard).

**`make evaluate`** → `evaluate_checkpoint`: `load_checkpoint` → `build_dataloaders` → `collect_predictions` on test → `compute_metrics` + `metric_confidence_intervals` (1,000 bootstraps) + `youden_threshold` → confusion/ROC/PR figures + `error_analysis` → `*_test_metrics.json`.

**`make quantize`** → `run_quantization_study`: evaluate FP32; `dynamic_quantize`; `static_quantize` (per-channel weights + histogram observers, calibrate on val); record size/acc/AUC/latency for each; `export_onnx` → `*_quantization.json` + comparison figure.

**`make benchmark` / `make memory`** → `benchmark_model` (disk size, warmup+repeat latency, throughput, peak RSS); `profile_streaming_vs_naive` (336 MB vs 3,141 MB) + `profile_runtime_memory` (FP32 980 MB vs INT8 164 MB).

**`make explain`** → `run_explainability`: predictions → pick correct/FP/FN → Grad-CAM++ on the last conv layer → overlays + grid figure.

**`make external-rsna`** → `fetch_rsna_hf.py` (download DICOM) → `build_rsna_subset.py` (DICOM→PNG, balanced 6,012/class) → `evaluate_directory` (zero-shot inference, separate `rsna_external` namespace) → `rsna_external_metrics.json`.

**`make verify-numbers`** → loads `results/metrics/*.json`, formats each headline number, and asserts it appears verbatim in `reports/thesis_final.md` (21/21).

## Part 5 — Methodology deep-dive (with the "why")

1. **Data & integrity.** Stratified 80/20 from train; official test held out. *Why dedup?* the raw split leaked 9 identical images across train/val (and 16 within-train duplicate groups), which would optimistically bias model selection — removed 26 files; test kept canonical.
2. **Preprocessing.** Resize→(random crop, flip, ±10° rotation, brightness/contrast) for train; deterministic resize+normalise for val/test. *Why?* augmentation reduces overfitting; deterministic eval = unbiased, reproducible metrics.
3. **Model + head.** Pretrained EfficientNet-B0 + small binary head. *Why EfficientNet-B0?* strong accuracy at ~5 M params (edge-friendly). *Why a shared head across 3 models?* makes the comparison fair (only the backbone differs).
4. **Staged transfer learning.** Freeze→train head→unfreeze→fine-tune at lower LR. *Why?* protects pretrained features early, adapts them later; stable + data-efficient.
5. **Training tricks.** AdamW + warmup/cosine + label smoothing + grad clip + early stopping. *Why each?* stable optimisation, less over-confidence, no wasted epochs.
6. **Evaluation.** Full metric panel + bootstrap 95% CIs + Youden. *Why CIs?* a point estimate hides uncertainty; CIs are expected in rigorous papers.
7. **Quantization.** Dynamic vs static INT8; per-channel + clean calibration. *Why static + per-channel?* dynamic barely compresses conv nets; per-tensor collapses EfficientNet — per-channel is necessary.
8. **Benchmarking.** Disk size, warmup+repeat latency, throughput, sampled peak RSS. *Why not tracemalloc?* it ignores tensor/library memory and gives meaningless numbers.
9. **Explainability.** Grad-CAM++ on correct/FP/FN. *Why qualitative only?* saliency≠validated localisation (Saporta 2022); honesty over over-claiming.
10. **External validation.** Zero-shot on RSNA, no tuning. *Why?* the strongest answer to "single-dataset" criticism; a drop is expected and informative.

## Part 6 — Results & how to interpret them

- **Internal (Kermany, n=624):** AUC **0.9678** [0.9504–0.9816], Sens 0.9667, Spec 0.8376, F1 0.9366. *Interpretation:* strong, well-bounded performance; sensitivity-leaning (good for screening). At Youden threshold (0.918) specificity rises to ~0.92.
- **Model comparison:** all >0.95 AUC; MobileNetV3-Small highest AUC (0.974) but 77 false positives vs EfficientNet-B0's 38 → **EfficientNet-B0 chosen for the best precision/specificity balance.**
- **Quantization:** static INT8 = 5.13 MB (−71%), ~8× faster CPU, ~6× less RAM, AUC 0.9444 (−2.34 pt). *Accuracy at fixed 0.5 drops more than AUC* because quantization shifts probability calibration — threshold-recoverable.
- **Memory:** streaming 336 MB vs naïve 3,141 MB (**9.4×**); INT8 inference 164 MB vs FP32 980 MB (**~6×**).
- **External (RSNA, n=12,024):** AUC **0.8892** [0.8825–0.8954], Sens 0.9553, Spec 0.6060. *Interpretation:* model still detects pneumonia under domain shift; more false alarms on adult normals; ~0.08 AUC drop is the **expected** cost — reported honestly.

## Part 7 — Limitations & threats to validity

1. Single-institution **pediatric** training data.
2. External validation is **one exploratory, zero-shot** probe (RSNA), simple label mapping — not multi-dataset, patient-level, or a clinical reader study.
3. Efficiency measured on **CPU/GPU as an edge proxy** (no physical Raspberry Pi / Jetson).
4. Explainability is **qualitative** (Grad-CAM++ not validated against expert boxes).
5. Class imbalance; subgroup fairness (age/sex/ethnicity) not assessed.
6. Static-PTQ accuracy depends on backend/observer/calibration.

## Part 8 — Anticipated defense questions & model answers

- **"What's novel — isn't pneumonia detection solved?"** The contribution is the *methodology*: an integrity-checked, reproducible, deployment- and memory-honest, externally-validated evaluation. Lightweight CNNs already classify pneumonia; honest, deployable evaluation is the gap.
- **"Why EfficientNet-B0 if MobileNetV3-Small has higher AUC?"** MobileNet wins AUC by 0.6 pt but doubles false positives (77 vs 38; specificity 0.67 vs 0.84). For a *screening* tool clinicians must trust, false-alarm rate dominates → EfficientNet-B0's balance/F1 wins; MobileNet is the minimum-footprint alternative.
- **"Why did RSNA AUC drop to 0.889?"** Domain shift (pediatric→adult, different scanners). A drop is expected; the value is that we *tested externally and reported it honestly* — no tuning to inflate it.
- **"Is the memory claim real? Earlier drafts said 0.1 MB."** That earlier figure used `tracemalloc` (Python-only) and was wrong. We measure **peak process RSS** with psutil sampling: 980 MB FP32 → 164 MB INT8; streaming 9.4× less than naïve.
- **"Why per-channel quantization?"** The default per-tensor static config collapsed EfficientNet-B0 to AUC ≈ 0.40; per-channel weights + histogram observers + clean calibration recovered it to 0.9444. It's a real, transferable finding.
- **"How do I know the numbers aren't made up?"** Every number is regenerated by `make reproduce` and machine-checked by `make verify-numbers` (21/21 match the result JSONs); each training run logs a `metadata.json` manifest.
- **"Did you deploy on real edge hardware?"** No — CPU is an explicit *proxy*; the thesis says "suitable for" deployment; on-device benchmarking is future work.
- **"Why not k-fold cross-validation?"** A single stratified split + bootstrap CIs is used (CIs quantify uncertainty); k-fold is reasonable future work. (The original draft's "5-fold AUC 0.9958" was fabricated and was removed.)
- **"Is this clinically usable?"** It is a research artifact / screening decision-support concept, **not** a medical device; it needs regulatory approval, prospective and reader-study validation.
